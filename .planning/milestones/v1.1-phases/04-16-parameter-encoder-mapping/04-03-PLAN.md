Research Pattern 3 (encoder ownership handoff — canonical sequence):
```python
# Mode 0 (Pan) activation:
# 1. Clear ALL mixer channel strip assignments (pan + sends) from top encoders
# 2. Release ShiftableDeviceComponent from device encoders
# 3. Enable and assign pan16_top to top encoders
# 4. Enable and assign pan16_enc to device encoders with bank nav buttons

# Mode exit (1/2/3) teardown — BEFORE assigning sends:
# 1. Release pan16_top from top encoders (set_parameter_controls(None))
# 2. Release pan16_enc from device encoders + clear bank nav buttons
# 3. Restore ShiftableDeviceComponent to device encoders
# 4. THEN assign top encoders to mixer sends per mode
```

ShiftableDeviceComponent.set_parameter_controls(None) side effects (from research):
- Also calls self._control_translation_selector.set_controls_to_translate(None) — correct, expected
- On mode restore: set_parameter_controls(self._device_controls) re-arms both device component and translation selector

    ```python
    def on_enabled_changed(self):
        # When EncoderUserModesComponent disables this component (shift mode switch),
        # release Pan16DeviceComponent instances to prevent stale encoder bindings.
        # Pitfall 6 guard: without this, device encoders keep controlling device params
        # after shift is pressed and encoder user mode changes away from mode 0.
        if not self.is_enabled():
            if self._pan16_top is not None:
                self._pan16_top.set_enabled(False)
            if self._pan16_enc is not None:
                self._pan16_enc.set_enabled(False)
        else:
            # Re-enable on component re-enable; update() will route correctly.
            if self._pan16_top is not None:
                self._pan16_top.set_enabled(True)
            if self._pan16_enc is not None:
                self._pan16_enc.set_enabled(True)
            self.update()
    ```
