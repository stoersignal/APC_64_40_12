# Phase 6: Create user manual - Context

**Gathered:** 2026-05-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Ship an end-user manual for the APC40 control surface script that an APC40 owner who is **not** a developer can follow start-to-finish: install the script, identify every control, understand the toggle/momentary model, and use every shipped controller feature (v1.0 + v1.1 + post-v1.1 v1.2 commits) **including the step sequencer** without reading source code. Format is a small bundle in `docs/`: an interactive HTML layout reference modeled directly on `example/lp-interactive-map.html` — including its **mode-repaint pattern** so encoder modes, matrix modes, and modifier overlays each redraw the relevant region — plus prose-heavy Markdown for install and troubleshooting, plus a Python-generated static SVG fallback.

</domain>

## Implementation Decisions

### Format & File Layout
- **D-01:** The manual is a **bundle in `docs/`**, not a single Markdown file. Three artifacts ship together:
  - `docs/manual.html` — interactive layout reference (HTML + inline CSS + inline JS, single file, modeled on `example/lp-interactive-map.html`)
  - `docs/INSTALL.md` — install + first-run walkthrough (DOC-01)
  - `docs/TROUBLESHOOTING.md` — failure modes + known limitations (DOC-08)
- **D-02:** `README.md` becomes a thin entry point: project blurb, credits, and three links (Install / Manual / Troubleshooting). The current install paragraph in README is moved into `docs/INSTALL.md`. Existing PDF reference (`APC_64_40_quickstart_guide_rev_1.pdf`) is **replaced** by a link to `docs/manual.html` and the new generated SVG.
- **D-03:** Static SVG layout reference ships alongside the interactive HTML. Generated by `docs/gen_apc40_layout.py` → `docs/apc40-layout.svg`, mirroring the example pipeline (`example/gen_svg.py` + `example/lp-pro-mk3-layout.svg`). The script is committed; the SVG is committed too (so users without Python can view it directly).

### Interactive HTML Scope (DOC-02, DOC-03, DOC-04, DOC-05, DOC-06, DOC-07, new DOC-09, new DOC-10)
- **D-04 (FLIPPED):** The interactive HTML implements **full mode-repaint UI** mirroring the Launchpad example's top-row Rec/Patt/Stut/Mac1-4/MashUp pattern. Clicking a mode button repaints the relevant region of the APC40 (encoder area for encoder modes, clip-grid area for matrix modes, full-controller overlay for modifier states). Tooltips remain on every control as detail-on-hover.
- **D-04a:** The HTML carries **three orthogonal mode selectors**, not one combined strip — they map to the script's actual mode infrastructure:
  - **Encoder mode strip** — Pan (default) / Send A / Send B / Send C / User1 / User2 / User3. Repaints the 8 top encoders + 8 device encoders + device bank buttons. Source: `EncModeSelectorComponent.py`.
  - **Matrix mode strip** — Clip Launch (default) / Session Overview / Note-Mode-1 / Note-Mode-2 / Note-Mode-3 / Note-Mode-4 / Note-Mode-5 / Note-Mode-6 / Step Sequencer. Repaints the 8×5 clip grid + Track Stop row. Source: `MatrixModesComponent.py` (modes 0–7) and `ShiftableSelectorComponent._step_sequencer_active` toggle (the 9th, Shift-engaged sequencer overlay). Note Mode 1–6 patterns/channels/notemaps come from `Matrix_Maps.py` — patterns are user-configurable.
  - **Modifier overlays** — Shift held (toggle) / Save mode (Shift+Tap Tempo held, toggle). These are not standalone modes but transient states. Activating them dims/highlights the affected buttons over whatever encoder/matrix mode is currently rendered, matching how the user would experience them on hardware. Source: `ShiftableSelectorComponent.py` (Shift overlay) + `APC_64_40_9.py` (save flow).
- **D-04b:** Default render = Pan + Clip Launch + no modifier overlay. Click a mode button to switch within its strip; click the same button again to revert to default. Modifier overlays toggle independently and stack on top of the active modes.
- **D-05 (EXPANDED):** Tooltips remain rich and surface behavioral detail that's not visible in the repaint:
  - Solo / Mute buttons → tooltip explains short-press toggle vs ≥400ms momentary, fires-at-press-down, multi-track independence (DOC-03)
  - Pan button → tooltip explains 16-macro mapping (top encoders → params 1–8, device encoders → 9–16, bank navigation on device row only) (DOC-04). Clicking the Pan button in the encoder mode strip repaints encoders to show this mapping.
  - Send A / Send B / Send C buttons → tooltip explains short-press toggle / long-press momentary revert to Pan (DOC-03). Clicking switches the encoder repaint to that send's level mapping.
  - Tap Tempo + Nudge buttons → tooltip explains variation save/recall flow including the Shift+Tap Tempo save-cancel safety on encoder touch (DOC-05). Activating the "Save mode" overlay repaints the Nudge buttons to show their save-slot meanings.
  - Top encoders + device encoders → tooltip explains ring-LED feedback in current encoder mode and ramp/interpolation absolute mapping (DOC-06)
  - Shift button → tooltip lists the Shift overlay including Shift+Nudge Back → lock-to-device toggle (DOC-07). Activating the Shift overlay repaints affected buttons to show their shifted meanings.
  - Step sequencer (when matrix mode strip is in Step Sequencer state) → grid cells get tooltips explaining step-on/off, bank pages, velocity, loop start/length, lane mute behavior (new DOC-09). Source: `StepSequencerComponent.py`.
  - Matrix modes — Clip Launch / Session Overview / Note-User Modes 1–6 (new DOC-10) → each mode in the matrix-mode strip has its own repaint of the 5×8 grid + Track Stop row:
    - **Clip Launch** — cells labelled with track/scene index, tooltip explains clip-launch behavior + Track Stop row stops clips per track + Scene Launch column fires scenes.
    - **Session Overview** — cells labelled as scene-bank blocks, tooltip explains zoomed-out navigation, jumping to clip pages.
    - **Note Modes 1–6** — cells colored per `PATTERN_N` from `Matrix_Maps.py`, labelled with note name derived from `NOTEMAP_N`, tooltip shows MIDI channel from `CHANNEL_N`, whether `IS_NOTE_MODE_N` (sends MIDI) or User Mode (no MIDI), whether `USE_STOP_ROW_N` is True, and a cross-reference: "Edit `Matrix_Maps.py` to change this layout." The HTML must reflect the **actual current defaults** in `Matrix_Maps.py` — read the file at write-time, do not hardcode an out-of-sync copy.
- **D-06:** Tooltip layout follows the example: `<strong>` heading + body description + optional `<div class="related">` cross-reference block. Reuse the example's tooltip CSS verbatim where practical.
- **D-06a:** Note/User Mode tooltips include a "Customizing this mode" related-block linking to a section in `docs/manual.html` (or `docs/MATRIX-MODES.md` — planner's call) that explains the `Matrix_Maps.py` format: PATTERN array (LED colors, 0=off, 1=green, 2=green blink, 3=red, 4=red blink, 5=yellow, 6=yellow blink, 7-127=green per file comments), CHANNEL (MIDI channel 0-15), NOTEMAP (8×8 cell-to-note grid), USE_STOP_ROW flag, IS_NOTE_MODE flag.

### Visual Style
- **D-07:** Reuse the example's dark theme, neon-accent palette, and CSS Grid layout approach. Shape the grid to APC40 dimensions:
  - 5×8 clip launch matrix (not 8×8) — repaints under matrix mode strip
  - 8 track-control columns (Solo/Mute per track — note Track Activator/arm-record buttons are NOT mapped by this script per DOC-08)
  - Track Stop row below the 5×8 (Clip Stop buttons; doubles as Note/User Mode bottom row when `USE_STOP_ROW_*` is True in Matrix_Maps.py)
  - 8 top encoders (rotary, with LED ring representation) — repaints under encoder mode strip
  - 8 device encoders + device bank nav — repaints under encoder mode strip
  - 9 sliders (8 channel + master) + crossfader (rendered as labeled rectangles, not interactive)
  - Transport row (Play/Stop/Record/Tap Tempo/Nudge ±/Detail View)
  - Scene launch column, track nav buttons, encoder mode strip (Pan/Send A/B/C/User1-3), matrix mode strip (Clip Launch / Session Overview / Note Modes 1-6 / Step Sequencer), Shift, modifier overlay toggles
- **D-08:** Inline everything. Single self-contained `manual.html` — no external CSS/JS files, no build step, no fonts beyond system fallbacks. Mirrors `example/lp-interactive-map.html` exactly.
- **D-08a:** Step Sequencer mode is rich: when active, the 5×8 grid shows step on/off cells, the Track Stop row shows bank pages, the Scene Launch column shows velocity/loop-length controls, lane mute buttons get a distinct color. Tooltips on each region explain the role. The HTML doesn't need to *animate* a playhead — static representation with explanatory tooltips is sufficient.
- **D-08b:** Modifier overlay rendering — when "Shift held" is on, affected buttons get a distinct outline/glow and their tooltips switch to the shifted meaning. When "Save mode" overlay is on, only Nudge ± buttons + ramp encoders are highlighted; the rest fades. Stacks visually on top of whatever encoder/matrix modes are current.

### Terminology
- **D-09:** Use **Ableton's canonical "variations"** (not the project-internal "snapshots") in all tooltips, prose, section headings, and identifiers. Rationale: discoverability — users searching Ableton's docs and forums will recognize the term. Internal git history and code may keep "snapshot" but user-facing docs use "variations" consistently.
- **D-10:** Drop the `_snapshot_` / `snapshot` wording from new doc artifacts. Where helpful, the first occurrence in each artifact may include a parenthetical "(saved here as Macro Rack variations)" but subsequent uses say "variations".

### Troubleshooting Scope (DOC-08)
- **D-11:** `docs/TROUBLESHOOTING.md` covers every failure mode and limitation enumerated in `REQUIREMENTS.md` DOC-08:
  - Handshake failures (script not appearing in Live's MIDI prefs, version mismatch, install path wrong)
  - Exclusive-solo bypass — pressing Solo on track A does **not** un-solo track B (we write `track.solo` directly; this is intentional)
  - Fixed 400ms long-press threshold (`LONG_PRESS_DELAY = 4` ticks at 100ms each) — not user-configurable
  - No per-track Send A/B/C buttons — APC40 hardware has global mode selectors only
  - No Track Activator (arm-record) buttons mapped — deliberate scope choice
- **D-12:** Each entry follows: **What you might see** → **Why it happens** → **What to do**. No "fix it in source code" guidance — this is end-user doc, not developer doc.

### Install Walkthrough Scope (DOC-01)
- **D-13:** `docs/INSTALL.md` covers Windows + macOS first-run install only. Linux users are not in scope (Ableton Live is not officially supported on Linux). Sections: download, place folder, select in Live's MIDI prefs (input/output rows + Track/Remote toggles), verify handshake (LED feedback), version compatibility (Live 11 + Live 12 confirmed working).
- **D-14:** Screenshots are NOT required — text-only is acceptable for v1.2. If text instructions feel ambiguous during writing, the planner may insert annotated screenshots, but they are not a planning prerequisite.

### Out of Scope for v1.2
- **D-15:** No developer documentation (architecture walkthrough, state-machine internals, extension guide) — those are `DEV-01` / `DEV-02` / `DEV-03` in `REQUIREMENTS.md` Future Requirements, deferred to a future milestone.
- **D-16:** No release notes / changelog — `REL-01` in REQUIREMENTS.md Future, deferred.
- **D-17:** No localization. English only.
- **D-18:** No video tutorials. Text + interactive HTML + static SVG only.

### Claude's Discretion
- Exact CSS variable names, color palette tweaks, and grid spacing — match the example's aesthetic but adjust for APC40 proportions.
- Tooltip content phrasing — keep voice consistent with the example's terse-then-related-block pattern.
- Filename casing inside `docs/` (e.g., `INSTALL.md` vs `install.md`). Default to UPPERCASE for prose docs to match `README.md` / `CLAUDE.md` repo convention.
- Whether the static SVG legend duplicates the interactive HTML's tooltip content or stays minimal (label-only). Default to minimal — the SVG is a printable fallback, not the primary reference.
- Whether `docs/INSTALL.md` includes a "deploying via Git clone vs ZIP download" section. Default to ZIP-first (matches existing README), Git as a one-liner aside.
- Whether to keep `APC_64_40_quickstart_guide_rev_1.pdf` in the repo (it pre-dates the script's customization). Default: keep it for now, but no longer reference it from README — superseded by `docs/manual.html` + `docs/apc40-layout.svg`.

<specifics>
## Specific Ideas

- The interactive HTML's value proposition is **"hover and learn"** — every control gets a useful tooltip, no required reading order. The user lands on `manual.html`, sees the APC40 in their familiar layout, and learns by exploration.
- The static SVG is **the printable fallback** — for users who want a wall poster or a non-interactive reference. Keep it minimal: labels only, no behavioral notes.
- Tooltip pattern from the example (verbatim — port to APC40 contexts):
  ```html
  <strong>Solo (Track 1) — Toggle / Momentary</strong>
  Short tap toggles solo on/off. Hold ≥400ms acts momentary —
  solo activates on press-down and reverts on release.
  <div class="related">
    <em>Long-press on already-soloed track:</em> temporarily inverts (un-solos) until release.
    <em>Multi-track:</em> Each Solo button operates independently.
  </div>
  ```
- README.md after rewrite is roughly 15–20 lines: one-paragraph project description, a "Documentation" section with three bullet links, and the existing Credits section preserved verbatim.
- The 5×8 clip-grid dimension difference from Launchpad's 8×8 is the main visual asymmetry — plan grid template areas accordingly. APC40 also has dedicated transport/control regions to the left and right of the grid that the LP example doesn't have.

</specifics>
