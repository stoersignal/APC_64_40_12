# Quick Task 260504-m2x — Drum Rack Mode

Add a track-selection-driven **Drum Rack Mode** to the APC40. When the selected track's first top-level device is a Live drum rack, the APC40 auto-enters the mode and retargets a specific subset of controls to drum-chain semantics:

| Surface section | Drum Rack Mode binding |
|---|---|
| 8 Track faders | `chain[i].mixer_device.volume` |
| 8 Track Mute buttons | `chain[i].mute` (v1.0 toggle/momentary) |
| 8 Track Solo buttons | `chain[i].solo` (v1.0 toggle/momentary) |
| 8 Track Control encoders | `chain[i].mixer_device.{panning|sends[0]|sends[1]|sends[2]}` per active sub-mode |
| Track Control mode buttons | **Observed** — selects encoder sub-mode (do not own) |
| Bank Select up/down | Scroll `_chain_offset` by 8 (when > 8 chains) |
| Stop All Clips button | LED = mode-active indicator; Shift+press = exit-this-track |

All other APC40 controls (clip matrix, scenes, transport, crossfader, master, prehear, Shift+Send A AutoFilter, Shift+Send B EQ Smart Control, Variations modes) preserve default behaviour.

Six locked decisions in `260504-m2x-CONTEXT.md` (D-01..D-06) — read those first.

## Architectural shape

`DrumRackModeComponent(ControlSurfaceComponent)` — modeled on the recently-shipped `EncoderAutoFilterComponent` (quick-260504-k6p):

```
__init__         — store refs to mixer, encoder_modes, session, parent, all captured controls
                   register timer callback (delegates to ChainToggleMomentaryHandler ticks)
on_selected_track_changed  — detect drum rack on new track; engage / disengage accordingly
on_track_list_changed      — prune _exited_tracks set of dead track-id keys
_detect_drum_rack          — walk track.devices, return first device with class_name == 'DrumGroupDevice'
_engage(drum_rack)         — capture + rebind faders/mute/solo/encoders/bank/stop-all-LED
_disengage()               — release captured controls; mixer.update() restores normal bindings
_handle_shift_stop_all     — Shift+Stop while active → add current track id to _exited_tracks; disengage
_on_chains_changed         — chain count listener; rebound _chain_offset; refresh bindings
_on_encoder_sub_mode_change — observe encoder_modes._mode_index; rebind chain encoders to pan/sendA/B/C
_dump_diagnostics_once     — first activation: log_message drum_rack class_name + chain count + chain[0] params
```

The component is **always alive** but only ACTIVE (engaged) when both:
1. `_detect_drum_rack(selected_track)` returns a device, AND
2. `id(selected_track) not in _exited_tracks`.

When inactive, every captured-button value listener is a passthrough no-op (returns immediately) so the underlying components see normal events.

## Per-chain mute/solo: ChainToggleMomentaryHandler

Reusing `ToggleMomentaryChannelStripComponent` directly is not possible — its state machine writes `self._track.solo / self._track.mute`, not `chain.solo / chain.mute`. To preserve v1.0 timing semantics without forking the proven press-timing logic:

1. Extract a **pure helper function** from `ToggleMomentaryChannelStripComponent._handle_toggle_momentary` into `ToggleMomentaryChannelStripComponent.py` module scope:
   ```
   def handle_toggle_momentary_press(value, target_obj, target_attr, state_dict, shift_pressed):
       """Press-down toggles target_attr on target_obj, captures pre-press state, starts countdown.
       Release reverts target_attr if state_dict['momentary_active'] is True.
       state_dict keys: 'ticks_delay', 'state_before_press', 'momentary_active'."""
   ```
   `ToggleMomentaryChannelStripComponent._handle_toggle_momentary` becomes a thin wrapper that builds `state_dict` from its own attributes — **no behavior change** for v1.0.
2. `ChainToggleMomentaryHandler` (private class inside `DrumRackModeComponent.py`) holds 8 chain-slot dicts; on press/release/timer-tick it calls the extracted helper with `target_obj=chain, target_attr='mute'/'solo'`.
3. The component drives ticks via its own `_register_timer_callback` (same pattern as the v1.0 component).

This keeps v1.0's tested code path intact while sharing the timing constant `LONG_PRESS_DELAY = 4` and the press/release semantics.

## Per-track exited-state storage

Set of `id(track)` ints, keyed at the moment of Shift+Stop. Pruned on `on_track_list_changed`: iterate `self.song().tracks` and `return_tracks`, intersect with stored ids; entries not found in either list are dropped (track was deleted in Live). Acceptable — the only way to repopulate is a fresh user gesture.

## Stop All Clips co-existence

The Stop All Clips button at MIDI note 81 is already shared by multiple consumers (`PedaledSessionComponent.set_stop_all_clips_button` AND `MatrixModesComponent` in Variations modes which adds its own listener). Drum Rack Mode follows the same pattern:

```python
self._stop_all_button.add_value_listener(self._stop_all_value)  # additional listener, never set_stop_all_clips_button(None)
```

`_stop_all_value` returns immediately (passthrough) unless **both** `is_active()` and `_shift_pressed` are true. Variations modes already coexist with the session's stop-all wiring; the same compositional approach works here.

LED control: Stop All Clips at note 81 is a plain `_Framework.ButtonElement`, which exposes `turn_on()` / `turn_off()` (verified via `MatrixModesComponent` and `EncoderEQComponent` usage). Wrap calls in `try/except` to mirror the project's fail-quiet idiom.

## Encoder sub-mode observation

`EncModeSelectorComponent._mode_index` (0=Pan, 1=Send A, 2=Send B, 3=Send C) is the source of truth for encoder routing. The new component **observes** the four mode buttons (`APC_64_40_9._global_bank_buttons`) by adding a secondary value_listener — on press, it reads `encoder_modes._mode_index` AFTER the existing handler has run (next timer tick) and rebinds the 8 chain encoders accordingly:

- Pan sub-mode → `chain[i].mixer_device.panning`
- Send A     → `chain[i].mixer_device.sends[0]`
- Send B     → `chain[i].mixer_device.sends[1]` (release if missing)
- Send C     → `chain[i].mixer_device.sends[2]` (release if missing)

When the mode is engaged, `EncModeSelectorComponent.update()` will still wire the per-strip pan/send controls — but the strips themselves are no longer the captured channels (faders are released in `_engage`), so its writes become harmless no-ops on dead mixer slots. Confirm this in Task 4 UAT.

10. **Variations modes coexistence.** Switch matrix to Variations mode (mode 7) → Stop All Clips becomes the randomize-macros button per existing behaviour. Switch back. Drum Rack Mode resumes (LED on if still on a drum-rack track).

## Out of scope (explicit)

- **Return chains** (`drum_rack.return_chains`) — only main `chains` are addressed in v1.
- **Recursion into nested instrument/effect racks** (per D-04 — top-level only).
- **Visual feedback on faders / mute-solo LEDs reflecting chain state in real-time when external automation moves them.** Encoder LED rings are already wired via `RingedEncoderElement`; mute/solo LEDs follow the v1.0 invert-feedback pattern via `set_invert_mute_feedback`. If chain.mute external listener feedback is missing on UAT, log it and defer.
