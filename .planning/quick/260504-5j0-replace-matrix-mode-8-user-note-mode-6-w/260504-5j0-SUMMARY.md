## Behavior contract (as implemented)

- **Pads (5×8 = 40)** — row-major mapping to variation indices 0..39 on `song().appointed_device`.
  - Green LED when `i < device.variation_count`; red when `i == device.selected_variation_index`; off otherwise.
  - Press: sets `selected_variation_index = i` and calls `recall_selected_variation()` instantly. Empty-slot presses are silently no-op.
- **Track Stop col 0** — yellow LED whenever the appointed device exposes `store_variation`. Press calls `device.store_variation()` and repaints LEDs.
- **Track Stop cols 1–7 / Scene Launch** — off and inactive in this mode.
- **No appointed device or non-Rack device** — all 48 buttons go off; presses are no-ops (guarded by `hasattr` on `variation_count` / `store_variation`).
- **Refresh moments** — mode entry; every pad press; every store press; on `appointed_device_changed` (when the listener API is available, guarded behind `try/except` so it stays safe across Live versions).

## Iteration history (notes for future similar tasks)

Three rounds of UAT-driven fixes were needed past the initial commit. The non-obvious gotchas:

- **`set_enabled(False)` on a matrix button kills MIDI listener routing** (`ConfigurableButtonElement.install_connections` skips the framework dispatch path). Pads need `set_enabled(True)` for `add_value_listener` to fire — `clip_slot.set_launch_button(None)` is enough to detach the standard clip-launch behavior without disabling the button itself.
- **Live's Song listener API is `add_appointed_device_listener`, not `add_appointed_device_changed_listener`.** The `_changed_` spelling silently fails `hasattr` and the listener never binds. EncoderDeviceComponent.py:50 is the canonical reference for this naming in this codebase.
- **`store_variation()` does not auto-update `selected_variation_index`.** Track the previous count; when it grows, set `selected_variation_index = new_count - 1` so the just-stored variation becomes active.
- **Live's `selected_variation_index` listener does not fire reliably immediately after a property write from this side**, so `_variations_pad_value` repaints synchronously after recall; the listener path remains wired as a redundant catch-up for external (UI / other-controller) changes.
