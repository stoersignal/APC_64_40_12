# Quick Task 260504-5j0 — Fix 1 (UAT-driven)

User reported, after the initial commit (`ecd2352`):

1. The Track Stop col-0 store button is not wanted — store is already on **Shift + Tap Tempo** (`ShiftableTransportComponent.py:158-176`). Remove it.
2. The pad LEDs do not update in real time — adding a variation via Shift+Tap Tempo (or in Live's UI) does not light a new pad. ("freezes only the amount of active leds")
3. Pressing pads in Variations Mode does nothing — neither selecting nor triggering works.

## Root cause for #3 (pads silent)

`MatrixModesComponent.py` was calling `button.set_enabled(False)` on every matrix pad before attaching the value listener. `ConfigurableButtonElement.install_connections` (`ConfigurableButtonElement.py:64-68`) only installs the framework's MIDI-event routing when `_is_enabled` is True; with the buttons disabled, hardware presses never reached `_variations_pad_value`, so neither `selected_variation_index` nor `recall_selected_variation()` were ever called.

## Root cause for #2 (LEDs frozen)

There were no Live API listeners on the appointed device. `_refresh_variations_leds` ran only on mode entry / on appointed-device-changed / on press — so any external change (Shift+Tap Tempo store, Nudge step, Live UI edit) went unseen by the grid.

## Fix

`MatrixModesComponent.py`:

- **Pads:** drop `set_enabled(False)`; pads stay `set_enabled(True)` so the framework routes MIDI events to my listener. `clip_slot.set_launch_button(None)` still detaches the standard clip-launch path so the pad fires _only_ my listener.
- **Store button:** entire `_variations_store_button` setup, listener (`_variations_store_value`), and stop-row teardown removed. Track Stop row is left at its default clip-stop wiring (already set up by the standard pre-mode block in `_set_modes`).
- **Real-time LEDs:** added `_variations_attach_device_listeners(device)` / `_variations_detach_device_listeners()` that hook `device.add_variation_count_listener(...)` and `device.add_selected_variation_index_listener(...)` (Live ≥ 11), each guarded by `hasattr` + `try/except` so older builds stay safe. New listeners `_variations_on_variation_count_changed` and `_variations_on_selected_index_changed` repaint when Live changes either value. The existing `add_appointed_device_changed_listener` rebinds these device listeners onto the new device whenever the user appoints a different Rack.
- **Press handler:** removed the explicit `_refresh_variations_leds()` after recall — the `selected_variation_index` listener handles repaint, avoiding a redundant paint.

`docs/manual.html` — `'Variations'` mode definition: store-button copy removed; Stop row described as "default clip-stop", with a pointer to Shift+Tap Tempo for store. Description text updated to mention real-time LED refresh.

`APC40_User_Manual.md` — Variations Mode section: store via Shift+Tap Tempo, real-time LED behavior called out.
